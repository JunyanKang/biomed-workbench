# 0.2.0-dev · 2026-08-06

[中文](2026-08-06.zh-CN.md) · [English](2026-08-06.md) · [版本索引](README.zh-CN.md)

本开发快照纳入截至第十四轮代码复审提出的科学门禁、版本恢复与方法修订改进。

## 科学门禁

- 外部结果契约现在绑定登记评定器的可调用身份、评定契约版本和插件内程序校验值；这些字段进入回执中的门禁结果及其校验身份。
- “需要科学复核”和“当前不可评定”只接受人工审议，虚构自动评定器身份不能把门禁改写为接受。
- 登记评定器真实返回“失败”时，系统保留实际执行回执、重读产物和自动拒绝记录，并要求严重或致命等级评审后选择排除、重跑、换方法或其他非保留动作。
- 容器或科学家族准入失败时，事务会回滚本次新导入的按内容寻址对象，不留下孤儿文件。

## 研究计划与状态恢复

- 评审触发的重跑与换方法新增公开准备路径。系统在科学决策前通过注册表创建子计划并冻结节点级修订契约；同一来源执行的全部输出必须共用动作、目标与请求身份。结构化参数调整使用与命令模块实际执行一致的规范化请求身份，未执行的下游工作按明确输出映射改接到替代节点产物。
- 可执行换方法与普通路由备选已经分开。只有带输入、输出、附加产物和参数映射的专用关系才能进行节点替换。冻结契约会明确结论范围是保持、改由目标方法独立举证，还是收窄。FastQC 与 fastp 登记为承担相同决策角色但门禁独立的方法，而不是指标层面的等价方法。
- 参数映射会先把来源参数转换为目标参数，再应用用户明确覆盖值；替代节点保存完整目标参数，恢复执行时不再重新猜测。
- 项目状态升级为 schema v2。第八轮提交 `10bafce` 真实生成的、含 3 条门禁审议的 v1 状态已作为回归夹具；迁移会验证旧摘要与事件链，从原回执恢复新增字段，并记录旧状态摘要和事件数。
- 已绑定旧证据地图的 v1 状态通过非覆盖式迁移入口恢复：先验证不可变发布目录，再列出真实缺失的科学依赖。旧格式没有保存事前准入时只记录“历史不可证明”，并精确绑定迁移来源、已验证地图、地图覆盖状态、假设和预期输出。永久历史限制与当前交付条件分别报告。
- 保留一份由上一版本真实生成的迁移契约 1.1.0 状态及其不可变地图目录。新的非覆盖式升级会验证旧状态、旧迁移与恢复摘要、事件链、地图文件、计划节点合同和真实覆盖关系，再写出带明确升级来源的 1.2.0 后继状态。
- 迁移契约升级凭据必须同时具有经验证的旧证据地图和旧分析准入恢复记录；缺少任一结构前提的状态会在重载时被拒绝，不能虚构发生过 1.1.0 至 1.2.0 的升级。
- 交付条件改为三态结果：未指定具体交付节点时写为“尚未评估”；只有正式校验器逐个检查指定节点后，才写为“满足”或“阻断”。
- 顶层帮助现在完整列出计划修订、v1 状态迁移和迁移契约升级入口，并引导使用项目级帮助查看全部参数。
- 对外期刊指引聚焦项目适配、官方作者指南和稿件要求。
