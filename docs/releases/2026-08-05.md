# 0.2.0-dev Scientific Admission Closure

- Date: 2026-08-05
- Status: family-level output admission and compatibility-bound return
- Languages: [English](2026-08-05.md) · [中文](2026-08-05.zh-CN.md) · [Version index](README.md)

## Scientific output admission

- The 82 generated output contracts now resolve to 18 explicitly implemented scientific families instead of mechanically unique fallback names.
- Every family fails closed for unknown media, has positive and adversarial negative fixtures, and reloads the declared scientific container rather than trusting a filename or caller label.
- JSON records, numeric tables, genomic intervals and PAF alignments, sequence and tree results, MatrixMarket counts, HDF5 single-cell objects, archives, coordinates, figures, reports, configurations, interactive HTML, and model bundles have family-appropriate structural and accounting checks.
- Functional enrichment cross-recalculates ORA/GSEA fields against input accounting; an internally consistent-looking table with contradictory tested or background denominators is rejected.
- Caller-supplied gate booleans are no longer accepted. Family admission and manifest gate adjudication are now separate; protocol `2.0.0` records each gate as passed, failed, requiring review or not evaluable, with the declared evidence-role digest. A family-valid file can no longer make unrelated design and claim gates appear passed.

## Runtime compatibility

- An external return must contain a structured runtime observation with one workflow, the complete selected-row tool and dependency sets, a version policy, and the compatibility-contract digest.
- Tool and dependency identities must exactly cover the frozen row. Every version is checked against its declared rule; a `tested` policy additionally requires an exact tested baseline.
- The same compatibility digest is frozen into the handoff and checked on return. Missing tools, missing dependencies, substitutes, forged workflow names, out-of-range versions, and unbound runtime objects are covered by negative tests.

## Delivery and receipt evidence

- All three registered publication-delivery modules now pass a real temporary-workspace evidence-map transaction. Controller resume reopens the configured immutable store before release; a missing map or tampered index leaves delivery awaiting a valid evidence map.
- Portable readiness identity remains deterministic. Each CI run now uploads a separate timestamped archive containing full controlled-fixture receipts and observed executor/runtime information, retained for 30 days.

## Validation scope

These admission changes do not reissue or upgrade historical public-data evidence. Existing scientific module versions remain unchanged because computation and templates were not modified; future handoffs distinguish the incompatible return protocol through explicit version `2.0.0` and its content digest.
