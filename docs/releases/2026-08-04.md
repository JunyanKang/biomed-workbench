# 0.2.0-dev Scientific Closure Update

- Date: 2026-08-04
- Status: execution-ingest and evidence-publication closure
- Languages: [English](2026-08-04.md) · [中文](2026-08-04.zh-CN.md) · [Version index](README.md)

## Observed-output semantics

- Agent-generated outputs now require a digest-bound semantic metadata artifact in addition to container reload validation.
- The plugin verifies the semantic validator source digest, invokes the registered validator itself, and computes every declared quality-gate result. Caller-supplied pass/fail claims are rejected.
- Functional enrichment now validates ORA/GSEA result columns, probability ranges, ratio consistency, overlap accounting, and method-specific score fields. Placeholder tables such as arbitrary `foo`/`bar` columns cannot satisfy the contract.
- All agent-generated output ports carry explicit semantic profiles and exact gate-evaluator coverage.

## Delivery authorization

- Publication delivery no longer depends on a final map that itself requires delivery to have completed.
- A delivery-authorization map binds one pending delivery node to its exact active plan, retained input artifacts, upstream completed nodes, admissions, reviews, decisions, and execution receipts.
- Authorization cannot be reused for another node or survive input, plan, review, or decision drift. The three registered delivery modules each have a positive reachable controller scenario.
- The final validated-delivery map remains a terminal archive created only after all retained deliverables have completed review.

## Recoverable publication and fixture evidence

- A publication transaction that stops at `prepared` may be explicitly aborted only while no immutable map, index entry, current pointer, or staging artifact has been published. Once publication evidence exists, abort is refused and recovery must complete the transaction.
- Run-specific controlled-fixture receipts now bind case, module, version, compatibility row, complete normalized output, validated projection, Python/kernel runtime, reload method, and round-trip kind. The deterministic cross-host readiness catalog uses a separate portable identity and does not mistake host-specific output or runtime bytes for release metadata.
- Execution readiness separately records process-JSON round trips and direct artifact-payload reloads; neither is represented as public-data or external-backend execution.

## Validation scope

These changes validate scientific admission and publication control behavior. They do not upgrade any module's external-tool or public-data maturity unless that module already has matching observed execution evidence.
