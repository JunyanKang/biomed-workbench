# 0.2.12 · 2026-09-03

[中文](2026-09-03-0.2.12.zh-CN.md) · [English](2026-09-03-0.2.12.md) · [版本索引](README.zh-CN.md)

本版本补齐普通项目分析报告的正式交付门禁。此前，论文和项目书写作已经要求生成并重新打开 HTML 报告，但一般分析报告仍可能只返回 Markdown 或内存中的结果页；现在二者已经明确分开并形成可执行约束。

## 分析报告交付

- 新增 `scientific-analysis-report-delivery`，把经过科学复核的观察、解释、实验或统计单位、证据边界和下一步决定写入带目录的 HTML 页面。
- 正式分析报告必须把 HTML 声明为主要文件并在交付前重新打开；Markdown 可以伴随保存，但不能单独满足交付要求。
- 页面至少连接一项真实的数据、图件、分析程序或文献来源。本地文件会重新计算校验值，声明值不一致时停止交付。
- 尚未完成科学复核的结果不能进入正式报告。对话中的简短回答、后台 JSON 记录及 FastQC、MultiQC 等工具原生质量报告继续使用各自适合的形式。

## 路由与项目入口

- “生成分析报告”“完整项目报告”“科学解读报告”等常见中英文请求会进入 HTML 报告交付模块。
- `project report` 可直接从持续项目的结果状态生成正式 HTML 报告；`project view` 仍用于快速查看，不再被误认为文件交付。
- 结果页在提供项目目录时会把已登记产物连接到报告，同时保留真实实验单位。

## 验证

受控测试覆盖普通分析报告路由、HTML 写出与重新读取、目录和证据链接、Markdown-only 拒绝、未复核结果拒绝，以及工具原生质控报告不被误路由。完整本地套件运行 1,376 项，其中 1,374 项通过，2 项按既定条件跳过；发布检查、隔离安装、插件契约和 6/6 严格健康检查通过。正式发布仍以同一提交的远端持续集成全部成功为准。
