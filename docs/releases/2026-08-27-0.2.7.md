# 0.2.7 · 2026-08-27

[English](2026-08-27-0.2.7.md) · [中文](2026-08-27-0.2.7.zh-CN.md) · [Release index](README.md)

This release promotes analysis environments from descriptive runtime notes to mandatory execution-chain identities. Repeat computation checks and reuses a recorded environment first, preventing dependency drift, duplicate installation, and silent replacement of an earlier result with a new runtime.

## Analysis-environment identity

- Every new observed execution receipt records the environment manager and name, interpreter version, platform, project lock-file digests, resolved package-inventory digest, and container-image digest.
- Research state retains a verifiable identity without exposing machine-local directories; the private project directory also stores an immutable record named by environment-content digest.
- Tool and dependency versions must still satisfy the module's selected compatibility profile. Environment identity does not replace software, data-format, or scientific quality checks.

## Repeat analysis and external workflows

- Before the same module version and compatibility profile run again, an exact or content-equivalent environment is reused without another installation.
- Changes in packages, lock files, interpreter, platform, or container image block local execution before computation. An intentional change requires a new analysis branch and renewed review.
- A legacy receipt without environment provenance cannot silently authorise a run in the current environment or reissue an earlier result.
- External workflow handoffs freeze acceptable prior environment-content digests. Returned outputs must include a complete environment identity and pass drift comparison before import.

## Use and validation

- `tools/workbench environment --project-root PROJECT` reports the current identity, matching history, reuse decision, and required action; optional module and compatibility-profile filters narrow the comparison.
- Local execution, project resume, and external result ingest persist every accepted identity in the project environment records.
- New tests cover successful reuse, content drift, external-return drift, identity tampering, and immutable record persistence.
- All 6 strict health checks passed; release validation covered 215 modules and 216 compatibility rows.
- The complete local regression suite ran 1,333 tests, with 2 declared skips and all remaining tests passing. Remote continuous integration is bound to the final release commit.
