# 安装与更新

语言：[中文](installation.zh-CN.md) · [English](installation.md)

## 安装

在 Codex 中直接说：

> 安装 [JunyanKang/biomed-workbench](https://github.com/JunyanKang/biomed-workbench) 这个仓库的当前发布版本。保留我现有的本地修改，完成后检查插件是否能够正常加载，并用自然语言告诉我安装版本和检查结果。

安装完成后，重新加载插件并开启一个新任务，让当前版本的研究入口和工具进入会话。

Biomed Workbench 的核心需要 Python 3.10 或更新版本。具体分析还可能需要 R、外部科学软件、数据库或容器环境；工作台会根据所选方法检查这些条件，不会因为插件本身安装成功就假定所有分析软件都已就绪。

## 更新

更新时可以说：

> 把 Biomed Workbench 更新到当前发布版本。先检查并保留未提交的本地修改；更新后重新加载插件，核对版本和能力清单，并运行发布完整性检查。

如果项目需要固定版本，请明确指定发行版本或提交。已经产生的研究结果仍保留其原始软件、参数和版本记录，不会因为插件更新而改写。

## 在其他智能体中使用

当前完整发布流程以 Codex 为主要使用环境。支持 Agent Skills 或类似技能目录的其他智能体可以读取同一研究入口；支持本地 MCP 的环境也可以读取能力清单和方法信息。

不同智能体对文件访问、运行环境、权限确认、网页操作和结果重读的支持并不相同，因此需要在实际环境中逐项确认。仓库中的 Codex 配置文件体积很小，其他智能体可以保留但不会自动使用。详细说明见[在不同智能体中使用](agent-integration.zh-CN.md)。

## 凭据

多数已接入的公共数据库支持匿名访问。`NCBI_API_KEY` 可选，用于提高 NCBI E-utilities 和 Datasets 的访问容量。AlphaFold Server 使用官方网页中的 Google 账号登录，由用户在网页中确认和提交；Biomed Workbench 不保存账号密码、访问令牌或浏览器会话。

用户可以让 Codex 通过隐藏输入配置、更新或删除凭据。敏感信息不会写入命令参数、分析输入、日志、报告或科学证据地图。各数据源的要求见[数据访问与凭据](data-access-and-credentials.zh-CN.md)。

## 常见问题

- **新能力没有出现：** 重新加载插件并开启新任务。
- **找不到仓库：** 使用完整 GitHub 地址，并确认需要的发行版本或分支。
- **Python 版本不兼容：** 提供 Python 3.10 或更新版本，无需长期全局激活某个环境。
- **某个分析软件不可用：** 让 Codex 检查现有环境，必要时为该方法建立隔离环境。
- **分析运行结束但没有形成结论：** 查看质量检查和科学评审；计算完成不等于结果已经可靠。

面向维护者的安装和发布检查见[开发与发布](development.zh-CN.md)。
