# 安装与更新

语言：[中文](installation.zh-CN.md) · [English](installation.md)

## 简要安装

把 `https://github.com/JunyanKang/biomed-workbench` 交给 Codex，并告诉它：

> 安装这个仓库的当前发布版本；核对 Codex 插件身份、统一研究入口、科学模块注册表和实际版本；保护现有本地修改；完成后用自然语言报告验证结果与当前项目仍缺少的科学后端。

首次安装或更新后，让 Codex 重新加载插件并开启一个新任务，使当前技能和工具入口进入会话。

## Codex 原生接入

Codex 读取 `.codex-plugin` 与 `.agents/plugins` 中的安装元数据，以 `skills/biomed-workbench/SKILL.md` 作为统一研究入口，并把内置图像生成等原生能力连接到明确的科学契约。这是本项目首先验证和发布的使用方式。

## 可选互操作适配器

- **Agent Skills：** 其他支持技能目录约定的智能体可读取同一份技能说明，但必须自行承担文件访问、权限确认、运行环境、产物重读和证据登记职责。
- **只读 MCP：** 支持本地标准输入输出 MCP 的智能体可注册 `tools/mcp_server.py`，获得能力发现、自然语言路由、契约查询和只读模块执行。写入型科研流程、Codex 原生工具和项目级科学决策不会通过 MCP 自动代理。

这些适配器位于科学模块之外，读取同一注册表，不复制模块、改写模板或换绑旧验收报告。详细边界见[可选互操作适配器](agent-integration.zh-CN.md)。

## 本地开发与更新

本地开发时，把稳定的仓库目录交给 Codex，要求它保留无关修改、报告源码修订与实际加载修订，并在修改后执行发布完整性检查。更新时指定分支或发行版本，重新加载插件，再核对模块注册表摘要；不得用远程版本静默覆盖本地未提交工作。

## 安装验证

Codex 在首次使用前运行严格健康检查，并报告插件身份、统一入口、模块数、注册表、路由、凭据策略和生成证据是否一致。核心需要 Python 3.10 或更新版本；启动器负责发现兼容解释器。具体科学软件、数据库和命令版本属于模块级兼容性与来源记录，核心健康检查不代表所有可选后端均已安装。

维护者的仓库级、发布级和隔离安装检查见[开发与发布](development.zh-CN.md)。

## 凭据

凭据需求按实际访问端点判断。当前实现的公共数据库端点大多匿名开放；`NCBI_API_KEY` 对 NCBI E-utilities 和 Datasets 是可选加速凭据。AlphaFold Server 则使用官方网页中的 Google 账号交互登录：Codex 只检查访问状态并生成提交包，用户在网页核对后手动提交，工作台不保存密码、令牌或浏览器会话。用户可以要求 Codex 通过隐藏输入检查、配置、轮换或删除 API 凭据；敏感值不得进入命令参数、模块输入、日志、报告、研究产物或科学证据地图。完整服务清单见[数据访问与凭据](data-access-and-credentials.zh-CN.md)。

## 常见问题

- **新能力未出现：** 重新加载插件并开启新任务。
- **仓库无法解析：** 使用完整 GitHub 地址并确认目标分支或发行版本。
- **核心运行时不可用：** 提供 Python 3.10 或更新版本；无需全局激活某个环境。
- **某个科学后端不可用：** 让 Codex 查找兼容的现有环境或建立隔离环境；只有真实运行和产物核查完成后，才登记该次分析结果。
- **结果未进入结论：** 查看模块指出的输入、兼容性或科学质量条件，并根据证据决定补数据、调参数或更换方法。
