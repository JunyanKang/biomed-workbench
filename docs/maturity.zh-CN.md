# 能力成熟度与证据等级

模块成熟度与某个项目的证据强度是两回事。`validated` 表示模块包、执行契约、兼容性组合、回归案例和代表性执行证据通过；它不表示对所有物种、实验、化学体系、队列和数据都自动有效。

| 证据层级 | 已证明 | 仍未证明 |
| --- | --- | --- |
| 契约 | 清单、格式、产物、质量门控和入口有效 | 真实运行和科学结果 |
| 兼容性 | 指定工具、依赖、平台和格式组合通过 | 其他版本、平台和设计 |
| 公开数据验收 | 当前工具或稳定公共数据通过预定门控 | 对其他数据和参数的推广 |
| 项目验证 | 用户真实输入运行、重读并通过项目门控 | 超出实验单位和观察证据的主张 |

`experimental` 表示模块已有可用契约与无需改源码的模板，但仍需更多后端、公共数据或真实项目验收。`agent_generated` 描述由 Agent 绑定参数并调用封装流程的执行方式，不是成熟度；计划本身不能进入证据地图。

发布状态分别报告八个维度：科学契约是否完整、封装实现是否在静态上可达、是否声明受控案例、受控案例是否带收据真实执行并重新读取、是否完成进程 JSON 往返、是否真正序列化并重新打开产物文件、是否存在当前代表性或公共案例验收、当前用户项目是否完成评审。案例文件只能证明“已声明”；隔离执行收据必须记录模块版本、兼容性组合、案例校验值、完整规范化输出校验值、验收投影校验值、实际运行版本、重读方式和往返类型。跨主机发布目录另行从案例、模块、兼容性条目、验收投影、重读方式和往返类型生成可移植身份；具体主机的完整输出及运行时校验值只保留在当次执行收据中，不进入确定性的发布元数据。进程返回对象与真实产物文件的重读不能混为一种证据。各维度不能合并成一个“成熟度数字”；代码可达不等于执行过，代表性案例通过也不等于当前项目结果已经产生并通过评审。所有通用入口的“科学完成”初始值均为否，必须由项目状态中的评审与决策更新。

外部流程返回的产物现在通过 18 个明确实现的语义家族进入工作台，不再为每个端口机械生成一个名称不同、逻辑相同的配置。每个家族都有封闭的文件类型分派、正向样例和对抗性负向样例；未知产物家族或未覆盖的文件类型直接拒绝。插件会按产物类型重新读取主要文件、压缩包、矩阵、HDF5 对象、坐标、表格、图件、报告或模型包，核对记录数与输入账目，并自行计算准入指标。调用方提交的质量布尔值已从允许的元数据结构中删除。这一步只证明返回产物符合冻结的结构和家族级科学约束，并把它送入项目评审，不能代替项目评审。

外部工作流的运行环境必须以结构化对象返回，其中包含实际工作流、完整工具集合、完整依赖集合、“复现已测试基线”或“落在兼容范围”策略，以及所选兼容性契约的校验值。工具和依赖名称必须与冻结条目完全一致，版本必须逐项满足规则；如果声明复现已测试基线，版本还必须与已登记测试版本精确一致。任务交接与结果回流必须绑定同一个兼容性契约校验值。缺少依赖、伪造替代工作流、版本越界或与任务交接不相干的运行环境对象都会被拒绝。

确定性的执行就绪文件继续用于跨主机发布比较。除此之外，每次持续集成都会单独上传一份带时间的本次运行回执，保留受控样例的完整输出校验值、实际运行版本、执行器信息和回执自身校验值，并保存 30 天。这份运行档案与版本库中的稳定目录分离，本身不会提高任何模块的科学成熟度。

最终结论以项目验证为准。完整项目验证必须经过分析准入、真实执行、产物按内容登记、结果重新读取、科学评审、明确决策和证据地图登记。未运行、失败或阻断的门控必须保留，进程退出为零也不能代替科学审查。
