# 在不同智能体中使用 Biomed Workbench

语言：[中文](agent-integration.zh-CN.md) · [English](agent-integration.md)

Biomed Workbench 目前以 Codex 作为主要发布和验证环境。科学方法、参数说明和能力清单保存在仓库中，因此其他支持技能目录或本地 MCP 的智能体也可以读取其中一部分能力。

## 支持程度

| 使用方式 | 可以使用的内容 | 需要另行确认的内容 |
| --- | --- | --- |
| Codex | 完整研究入口、文件处理、环境协作、网页交互、结果重读和项目交付 | 每个科学方法仍需满足自身的软件、数据和实验设计条件 |
| 支持 Agent Skills 的智能体 | 研究流程、方法说明和模块入口 | 文件权限、命令执行、环境隔离、结果重读和证据整理 |
| 支持本地 MCP 的智能体 | 能力查询、问题路由、方法信息和受限的只读调用 | 写入项目、外部软件、网页认证、作图和完整科研交付 |

能够读取技能说明，只表示该智能体看得懂入口，不表示它已经具备完整的执行环境。使用其他智能体时，应先确认它是否能访问项目文件、运行所需软件、重新打开结果并完成科学评审。

部分步骤依赖 Codex 自带的工具。其他智能体只有在提供并验证等价能力后才能完成这些步骤；否则相应工作应保持未执行。

## 仓库中的 Codex 文件

完整下载仓库时会同时得到 `.codex-plugin` 和 `.agents/plugins`。这些文件用于 Codex 安装，体积很小；其他智能体可以保留但不会自动加载，也不会因此被当成 Codex 插件。

科学模块只有一份。其他智能体读取同一能力清单，不应复制分析模板、改变质量标准或把旧的验收结果改写成新的执行证据。

## 给其他智能体的安装请求

可以这样说：

> 获取 [JunyanKang/biomed-workbench](https://github.com/JunyanKang/biomed-workbench) 的当前发布版本。如果你支持 Agent Skills，请加载 `skills/biomed-workbench/SKILL.md`；如果只支持本地 MCP，请先读取可用能力。请说明你能否访问项目文件、运行外部科学软件、重新读取结果并完成科学评审，不要把读取到能力清单当成已经完成分析。

如果智能体缺少某项能力，相应分析应保持未执行，或由用户改用已经验证的环境继续完成。

面向集成开发者的接口和测试要求见[开发与发布](development.zh-CN.md)。
