# Codex 优先与跨宿主互操作

语言：[中文](agent-integration.zh-CN.md) · [English](agent-integration.md)

Biomed Workbench 是智能体驱动的生物医学研究工作台，并以 Codex 作为首要参考宿主发布。`.codex-plugin`、`.agents/plugins` 和 `skills/biomed-workbench/SKILL.md` 共同定义当前完整验证的产品路径；Codex 的文件访问、权限确认、运行环境协作、原生图像生成和项目级交付共同构成这一参考实现。

“Codex 优先”描述的是验证顺序与支持深度，并不表示科学注册表只能由 Codex 使用。其他智能体可以通过标准技能目录或受限 MCP 接口接入；适配层位于科学模块之外，不复制参数化模板、改写质量门控或换绑既有验收报告。其他宿主只有在独立补齐并验证对应责任后，才能宣称完成相同的科研节点。

| 能力边界 | Codex 参考路径 | Agent Skills 宿主 | 只读 MCP 宿主 |
| --- | --- | --- | --- |
| 读取统一技能与科学注册表 | 完整验证 | 可读取；需宿主验证加载行为 | 可通过受限接口读取 |
| 文件写入、权限确认与环境管理 | 由 Codex 产品路径承担 | 由宿主自行实现与验收 | 不提供 |
| 外部科学软件与网页认证 | 按模块契约交互执行 | 由宿主自行实现与验收 | 不提供 |
| 产物重读、科学评审与证据地图 | 完整发布流程覆盖 | 由宿主自行实现与验收 | 只返回受限执行结果，不构成项目交付 |
| 宿主原生图像生成和协作交接 | Codex 原生能力 | 需要独立验证的等价能力 | 不提供 |

## Agent Skills 适配

支持 Agent Skills 或等价技能目录约定的智能体可以读取 `skills/biomed-workbench/SKILL.md`，并复用其中的研究流程和模块入口。该能力属于入口兼容，而非全流程认证：宿主需要自行提供文件访问、命令执行、权限确认、运行环境隔离、产物重读和证据登记。无法满足某项职责时，相应节点保持未执行。

## 只读 MCP 适配

`tools/mcp_server.py` 提供四类受限工具：能力列表、自然语言路由、单个能力契约查询和只读模块执行。它读取与 Codex 插件相同的注册表和 runner，不维护第二份科学目录。

MCP 不代理写入型科研流程，不代替 Codex 原生图像工具，不自动创建运行环境，也不把路由计划视为科学结果。需要写入项目、调用外部科学软件或形成项目结论时，宿主必须按模块契约自行完成授权、执行、产物核查与证据登记。

## 不变边界

- 新增宿主只增加适配器，不复制或改写科学模块。
- 适配器变化只触发适配器测试，不使旧科学验收报告失效。
- 所有入口读取同一模块注册表；能力数量和契约必须一致。
- `access: codex_native` 继续表示 Codex 原生工具交接。其他宿主只有具备经过独立验证的等价实现时才能完成该节点。
- `access: agent_generated` 是历史注册字段，表示由 Codex 管理的已打包参数化流程，不授权临时修改模板或任意生成分析代码。

## 验证要求

Codex 参考路径由完整发布验证覆盖。可选适配器通过独立边界审查，核对其文件位置、只读权限、注册表同源性和无科学模块反向依赖。边界审查只证明接口没有分叉或越权，不能证明某个外部宿主已具备完整科研执行能力，也不能提高科学模块的成熟度或替代公共数据、真实服务结果或真实项目验收。
