# 可选互操作适配器

语言：[中文](agent-integration.zh-CN.md) · [English](agent-integration.md)

Biomed Workbench 首先是 Codex 插件。`.codex-plugin`、`.agents/plugins` 和 `skills/biomed-workbench/SKILL.md` 共同定义经过发布验证的原生入口；Codex 的文件访问、权限确认、原生图像生成与项目协作能力构成完整产品体验。

其他智能体可以接入，但接入方式保持在独立适配层，不进入科学模块、参数化模板、质量门控或既有验收报告。

## Agent Skills 适配

支持技能目录约定的智能体可以读取 `skills/biomed-workbench/SKILL.md`，并复用其中的研究流程和模块入口。该兼容性属于说明级适配：宿主需要自行提供文件访问、命令执行、权限确认、运行环境隔离、产物重读和证据登记。无法满足某项职责时，相应节点保持未执行。

## 只读 MCP 适配

`tools/mcp_server.py` 提供四类受限工具：能力列表、自然语言路由、单个能力契约查询和只读模块执行。它读取与 Codex 插件相同的注册表和 runner，不维护第二份科学目录。

MCP 不代理写入型科研流程，不代替 Codex 原生图像工具，不自动创建运行环境，也不把路由计划视为科学结果。需要写入项目、调用外部科学软件或形成项目结论时，宿主必须按模块契约自行完成授权、执行、产物核查与证据登记。

## 不变边界

- 新增宿主只增加适配器，不复制或改写科学模块。
- 适配器变化只触发适配器测试，不使旧科学验收报告失效。
- 所有入口读取同一模块注册表；能力数量和契约必须一致。
- `access: codex_native` 继续表示 Codex 原生工具交接。其他宿主只有具备经过独立验证的等价实现时才能完成该节点。
- `access: agent_generated` 是历史注册字段，表示由 Codex 管理的已打包参数化流程，不授权临时修改模板或任意生成分析代码。

## 验证要求

Codex 原生入口由完整发布验证覆盖。可选适配器通过独立边界审查，核对其文件位置、只读权限、注册表同源性和无科学模块反向依赖。适配器验收不能提高任何科学模块的成熟度，也不能替代公共数据或真实项目验收。
