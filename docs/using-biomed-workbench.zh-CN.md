# 使用 Biomed Workbench

语言：[中文](using-biomed-workbench.zh-CN.md) · [English](using-biomed-workbench.md)

## 从研究问题开始

直接说明生物学问题、已有数据、实验设计和希望得到的结果即可。用户不需要记住模块名称，也不需要自己串联多个工具。

一个清楚的请求通常包括：

- 科学问题或需要比较的假设；
- 样本、物种、实验体系、平台或分子对象；
- 可用文件和关键元数据；
- 对照、批次、供体、条件、时间点和参考版本；
- 希望得到的图、表、结论、稿件内容或下一步决策。

如果关键信息可以从项目文件中安全确认，工作台会先检查文件。只有缺失信息会实质改变分析时，才需要用户补充。

## 一次完整分析包含什么

工作台会根据问题选择合适的方法，并依次完成：

1. 检查研究设计、实验单位、输入文件和元数据；
2. 写明工作假设、备选解释和判断标准；
3. 确认方法适用范围、软件兼容性和关键参数；
4. 使用真实项目数据运行已封装的流程；
5. 重新打开输出文件，检查技术质量、统计设计和生物学合理性；
6. 根据结果决定保留、限制解释、重新分析、换方法或补充数据；
7. 整理可追溯的图表、方法、结论和中英文报告。

计算结束并不自动代表分析完成。结果需要通过相应检查并完成科学评审，才能用于支撑项目结论。失败、阴性结果和互相冲突的证据也会保留。

## 项目中的几个检查点

- **接收数据：** 样本设计、文件、元数据、参考版本和格式是否一致。
- **准备分析：** 统计单位、混杂因素、方法选择和预期产物是否明确。
- **审查结果：** 技术质量、效应大小、稳健性、阴性结果和竞争性解释是否充分。
- **形成结论：** 每个关键结论有哪些支持、反驳和适用边界。
- **完成交付：** 图、表、方法、引用和文字解释是否彼此一致。

重要结果会进入[科学证据地图](scientific-evidence-map.zh-CN.md)，把前置数据、分析程序、作图数据、最终文件、图注、来源和研究决策连接起来。中文和英文报告使用同一版本的证据。

## 示例请求

> 分析这个 bulk RNA-seq 项目，考虑供体和批次，完成差异表达、通路与网络解释、敏感性检查和论文图；如果主比较不成立，请重新评估假设。

> 为这些 H5AD 文件设计并执行单细胞分析，比较整合与注释方法，保留未知细胞状态，并把通过评审的结果整理为稿件结果部分。

> 整理这个靶点在 PubMed、UniProt、ClinVar、临床试验、PDB 和 AlphaFold DB 中的证据，统一标识符，并区分已证实发现与待验证假设。

> 审查这套蛋白结构与分子对接结果，检查结构质量、界面可信度和对接构象，并提出可以验证的实验方案。

## 可能的交付物

根据任务不同，输出可以包括数据清单、分析计划、质量报告、统计表、图、方法、结果解读、稿件、审稿回复、专利材料或汇报文件。每份交付物都会区分已经执行的结果、基于证据的推断、未通过的检查和仍待解决的问题。
