# 使用 Biomed Workbench

语言：[中文](using-biomed-workbench.zh-CN.md) · [English](using-biomed-workbench.md)

## 从研究问题开始

直接说明生物学问题、已有数据、实验设计和希望得到的结果即可。用户不需要记住模块名称，也不需要自己串联多个工具。

一个清楚的请求通常包括：

- 科学问题或需要比较的假设；
- 样本、物种、实验体系、平台或分子对象；
- 可用文件和关键元数据；
- 对照、批次、供体、条件、时间点和参考版本；
- 希望得到的图、表、结论、稿件内容或下一步决策。

如果关键信息可以从项目文件中安全确认，工作台会先检查文件。只有缺失信息会实质改变分析时，才需要用户补充。

## 一次完整分析包含什么

工作台会根据问题选择合适的方法，并依次完成：

1. 检查研究设计、实验单位、输入文件和元数据；
2. 写明工作假设、备选解释和判断标准；
3. 分别识别实验类型、靶标、对照、归一化和待判断的生物学关系，并为每个问题选择一个主分析和一个必要的正交验证；
4. 使用真实项目数据运行已封装的流程；
5. 重新打开输出文件，检查技术质量、统计设计和生物学合理性；
6. 根据结果决定保留、限制解释、重新分析、换方法或补充数据；
7. 将结果归入正式、候选、敏感性或弃用状态，再整理可追溯的图表、方法、结论和中英文报告。

计算结束并不自动代表分析完成。结果需要通过相应检查并完成科学评审，才能用于支撑项目结论。失败、阴性结果和互相冲突的证据也会保留。

长期项目会建立[项目锁定配置](project-governance.zh-CN.md)，固定样本表、参考版本、细胞注释、重复单位、分析环境、阈值、颜色、正式目录和论文图登记表。每次真实执行都会记录 Conda、虚拟环境或容器的内容身份；重复分析前先复用核对通过的环境，环境变化则在计算前停止。日常结果页面优先显示科学结论、关键结果、证据边界和下一项决策；完整运行与追溯记录保留在后台，需要时再展开。

## 选择适合当前阶段的工作节奏

- **探索：** 快速检查候选方向、参数和图形，结果明确保留为候选、敏感性或弃用内容。
- **定稿：** 固定实验单位、输入、方法、参数、环境、作图数据、正式脚本和允许得出的结论。
- **投稿准备：** 在正式结果基础上完成独立复现、最终图件复核、公开文件检查和稿件一致性检查。

已有大量文件的项目不需要重新搭建。请直接说明项目目录和当前权威结果位置，工作台会先进行只读盘点，提出“图件—作图数据—分析脚本—排图程序—图注”的候选关系；研究者确认后，这些关系才进入正式项目记录。更完整的科学解释与图件叙事方式见[科学解释、研究叙事与结果决策](capabilities/scientific-interpretation-and-storytelling.zh-CN.md)。

## 项目中的几个检查点

- **接收数据：** 样本设计、文件、元数据、参考版本和格式是否一致。
- **准备分析：** 统计单位、混杂因素、方法选择和预期产物是否明确。
- **核对环境：** 是否存在可复用的既有环境，软件包、锁定文件、解释器、平台和容器身份是否与历史运行一致。
- **审查结果：** 技术质量、效应大小、稳健性、阴性结果和竞争性解释是否充分。
- **形成结论：** 每个关键结论有哪些支持、反驳和适用边界。
- **完成交付：** 图、表、方法、引用和文字解释是否彼此一致。

重要结果会进入[科学证据地图](scientific-evidence-map.zh-CN.md)，把前置数据、分析程序、作图数据、最终文件、图注、来源和研究决策连接起来。每个版本提供一个 HTML 阅读入口、中英文报告和中英文证据地图；页面内有目录，并可直接打开登记数据、程序、图件、图注和原始研究。Markdown、JSON 和关系表仍随版本保存。中文和英文报告使用同一版本的证据。

## 论文、基金和投稿任务怎样提出

写作任务可以从一段文字、已有稿件或完整项目开始。请尽量提供现有数据与图表、研究设计、已经确认的结论、参考文献、目标读者，以及希望完成的文章类型或章节。已有稿件还应说明哪些内容允许重写、哪些结构必须保留，以及是否已有目标期刊或审稿意见。

工作台会按任务需要组合以下工作：

1. 核对文献、项目事实、图表和引用，建立可以写入正文的主张及其证据边界；
2. 规划论文或基金申请的中心论点、章节任务和图件位置，再撰写或修订文字；
3. 复核数字、结果、公式、专业术语和引用是否在修订前后保持一致；
4. 检查实验单位、统计报告、数据与代码可用性，以及目标期刊和文章类型要求；
5. 根据真实审稿意见组织逐条回复、修订位置和仍需作者补充的内容；
6. 重新打开最终文稿、图件或演示文件，检查交付内容，而不是只提供提纲。

如果只提供稿件文字，工作台会审查和改写已有内容，但不会把未提供的数据、实验、引用、作者贡献或期刊要求补写成事实。国家自然科学基金申请还应提供项目类型和从官方系统下载的当年申请书；工作台分别处理青年 C、青年 B、青年 A、面上、地区、重点和重大项目，并在科学依据充分后继续完成实际正文，而不是只返回检查报告。完整能力见[科研写作、发表与转化交付](capabilities/publication-and-translation.zh-CN.md)和[国家自然科学基金申请书研究与写作](capabilities/nsfc-proposal-writing.zh-CN.md)。

## 示例请求

> 分析这个 bulk RNA-seq 项目，考虑供体和批次，完成差异表达、通路与网络解释、敏感性检查和论文图；如果主比较不成立，请重新评估假设。

> 为这些 H5AD 文件设计并执行单细胞分析，比较整合与注释方法，保留未知细胞状态，并把通过评审的结果整理为稿件结果部分。

> 这是一个已经分析多轮的项目。只读扫描当前结果目录，识别正式图件、作图数据、脚本和图注之间的候选关系；先让我确认冲突版本，再建立后续分析所需的项目记录。

> 整理这个靶点在 PubMed、UniProt、ClinVar、临床试验、PDB 和 AlphaFold DB 中的证据，统一标识符，并区分已证实发现与待验证假设。

> 审查这套蛋白结构与分子对接结果，检查结构质量、界面可信度和对接构象，并提出可以验证的实验方案。

> 根据这些结果表、论文图、方法记录和已核对文献，建立论文的核心论点和章节结构，撰写 Results 与 Discussion，并标出每项结论对应的图表、引用和证据边界。

> 审查这份基金申请的科学问题、研究目标、可行性证据和备选方案，再改进学术表达；不要虚构初步结果、合作条件或申请要求。

> 这是 2026 年国家自然科学基金面上项目。读取我从官方系统下载的申请书和现有 Word 草稿，核对立项依据、研究内容、研究基础、核心表型、机制证据和中英文摘要；最后检查引文编号并逐页复核版式，不要直接生成整本申请书。

> 根据编辑和审稿人原文制作逐条回复，核对每项答复对应的分析、实验、图表、引用和稿件位置；未完成内容保留为作者待办。

## 可能的交付物

根据任务不同，输出可以包括数据清单、分析计划、质量报告、统计表、图、方法、结果解读、稿件、审稿回复、专利材料或汇报文件。每份交付物都会区分已经执行的结果、基于证据的推断、未通过的检查和仍待解决的问题。
