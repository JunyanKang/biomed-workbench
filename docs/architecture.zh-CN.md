# 架构与扩展方式

语言：[中文](architecture.zh-CN.md) · [English](architecture.md)

本页面向希望了解项目结构或新增科学方法的读者。日常研究使用不需要理解这些实现细节，可直接查看[使用指南](using-biomed-workbench.zh-CN.md)。

## 总体结构

Biomed Workbench 只提供一个统一研究入口。用户描述科学问题后，工作台从版本化的独立模块中选择合适方法，并根据数据依赖组织执行顺序。

主要部分包括：

- **研究入口：** 理解用户目标，检查项目背景并选择方法；
- **科学模块：** 分别定义方法用途、输入、输出、参数、适用条件和质量检查；
- **项目记录：** 保存假设、分析计划、实际结果、评审和科学决策；
- **执行与协调：** 检查软件兼容性，运行分析并重新打开输出；
- **公共数据服务：** 访问经过限制的数据库端点，并按服务管理凭据；
- **科学证据地图：** 把保留的结果与其来源、图表、引用和后续决策连接起来。

能力清单由模块自动生成，不在路由程序或文档中另外维护一份。这避免了“文档写了某项能力，但实际注册表没有”或不同入口显示不同数量的问题。

## 一个模块需要说明什么

每个科学模块至少需要明确：

- 科学目的、适用场景和不能支持的结论；
- 输入数据、必要元数据、输出内容和文件格式；
- 可以调整的参数及其依据；
- 软件、依赖、平台和版本范围；
- 技术、统计和生物学质量检查；
- 可以替代或补充它的方法；
- 代表性成功、边界和失败测试。

需要计算的生物信息学模块还必须提供可直接绑定项目参数的实际流程。用户不需要修改分析模板源码。

## 项目结果怎样流转

一个结果通常经历分析准备、真实执行、输出重读、科学评审和保留或排除决策。只有完成这些步骤的结果才会进入科学证据地图。计算失败、质量不足和与假设冲突的结果会保留，但不会被包装成成功结论。

大型文件保存在项目自己的结果空间中，项目记录使用相对身份和内容指纹定位文件，避免把开发者机器路径写入可分享的研究记录。

## 新增或更新方法

新增方法应建立独立模块，不需要为每种工具增加新的用户入口，也不应在路由程序中写入特殊判断。修改后需要重新生成能力清单并完成模块测试、集成测试和发布检查。

软件版本变化并不一律要求重新计算：只有科学实现、参数含义、输入处理或结果识别发生改变时才需要重跑；文档、目录或无关模块变化不会使既有科学结果自动失效。

完整目录、开发命令和发布要求见[开发与发布](development.zh-CN.md)。共享文件要求见[格式与数据要求](format-contracts.zh-CN.md)。
