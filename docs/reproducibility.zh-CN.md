# 可重复性与兼容性

语言：[中文](reproducibility.zh-CN.md) · [English](reproducibility.md)

## 软件和分析环境怎样处理

科学软件版本、依赖解析、参考资源和运行环境都会影响输入格式、默认参数、输出字段和数值结果。Biomed Workbench 不只记录单个工具版本，还会为每次真实执行保存一份分析环境身份，包括环境管理器（如 Conda、Mamba、虚拟环境或容器）、环境名称、解释器版本、操作系统与处理器架构、项目锁定文件的校验值、已解析软件包清单摘要和容器镜像摘要。环境的本地位置以校验值保存，避免把私人目录写入可共享的研究状态。

文档中列出的具体版本是**可重复性基线**，用于说明代表性案例在什么条件下通过；它们不是所有项目都必须安装的固定版本。处于已声明兼容范围内的其他版本可以使用，但仍要通过相应的输入、输出和质量检查。

如果缺少必要软件或当前版本不兼容，工作台仍可帮助制定方案和准备输入，但不会把该分析写成已经执行。环境调整会在用户授权和资源允许的范围内进行。

## 重复分析前怎样避免环境漂移

同一项目再次运行同一模块和兼容配置前，工作台会读取既有执行回执并比较环境内容：

- 环境身份完全一致时，直接复用，不重复创建或安装；
- 环境移动到新位置但锁定文件、软件包、解释器版本和平台一致时，登记为内容等价的迁移后复用；
- 软件包、锁定文件、解释器、平台或容器镜像发生变化时，在计算开始前停止，不能把新结果覆盖到原分析链；
- 旧记录没有环境信息时，先恢复和核实原环境，不能凭当前环境重新签发旧结果。

确需升级软件、调整依赖或改变计算平台时，应建立明确的新分析分支，说明变化原因，并重新完成兼容性、结果重读和科学评审。模板在分析过程中不会自行安装依赖；只有在确认项目中没有可复用环境、安装范围得到允许且资源足够时，才会准备隔离环境。

项目环境记录保存在项目私有目录的 `.biomed-workbench/environments/` 中，并同时绑定到执行回执。可在运行前让智能体检查当前环境，或使用 `tools/workbench environment --project-root 项目目录` 查看复用状态；指定模块和兼容配置后，可以只核对相关历史运行。

## 一份结果怎样做到可追溯

每次实际分析应保留：

1. 科学目的、适用条件和输入要求；
2. 使用的软件、版本、分析环境、参数、随机种子和参考数据；
3. 输入文件、输出文件和质量检查结果；
4. 统计与生物学评审；
5. 采用、限制、排除或重新分析的理由。

这样既能重新运行计算，也能解释为什么当时接受或拒绝某个结论。仅仅得到退出状态为成功，并不能代替结果检查。

## 文件与参考版本

测序数据、比对文件、基因组区间、表达矩阵、单细胞对象、表格和图像都有各自的格式要求。工作台会检查压缩与索引、排序、坐标系统、基因组版本、注释、基因标识符、方向性和必要元数据。详见[格式与数据要求](format-contracts.zh-CN.md)。

## 凭据与外部服务

API key 和网页账号仅用于访问相应服务，不会写入分析产物、报告、示例或版本库。各服务是否需要凭据以及如何安全配置，见[数据访问与凭据](data-access-and-credentials.zh-CN.md)。
