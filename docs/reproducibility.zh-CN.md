# 可重复性与兼容性

语言：[中文](reproducibility.zh-CN.md) · [English](reproducibility.md)

## 版本策略

科学软件版本会影响可接受输入、默认参数、输出字段和数值结果。Biomed Workbench 因此把版本视为 provenance 和兼容性证据，而不是所有用户项目都必须固定的安装钉子。

每个科学模块需要声明：

- 接受的输入和输出契约；
- 保守兼容性策略；
- 已在验证中观察到的可重复性基线；
- 已知科学边界和格式边界；
- 输出进入项目证据前必须通过的检查。

文档中出现的具体版本是**可重复性基线**，不是对所有用户项目的强制安装要求。执行时，工作台记录实际检测到的版本，并标注它是否匹配已测试基线。处于声明兼容策略范围内的版本可以执行，但输出必须通过契约和代表性检查。

当科学后端缺失或不兼容时，路由和指导仍然可用；执行证据会被保留为未完成，直到出现兼容环境或经过验证的替代方案。插件不会静默改写用户环境，也不承担基础设施管理职责。

## 证据层级

可重复性由多个相互连接的层级表示：

1. **模块契约：** 科学目的、输入、输出、兼容规则和质量门控。
2. **代码模板：** agent 可根据项目改写的实质性参考实现。
3. **执行 provenance：** 实际工具、版本、参数、输入、输出摘要和观察到的检查结果。
4. **科学证据：** 通过技术和科学门控后的解释性结果。
5. **决策记录：** 为什么某个假设、流程或主张被接受、修正、拒绝或保留为未解决。

完成一个计算流程不自动等同于形成科学证据。只有通过模块契约和项目质量检查的输出，才能进入证据链。

## 格式契约

共享 profile 覆盖测序、比对、变异、区间、表达矩阵、单细胞、表格和图像等基础格式。模块继承这些格式规则，包括压缩、索引、排序、坐标系统、参考版本、注释、identifier、manifest、方向、元数据和 payload 角色。详见：[格式契约](format-contracts.md)。

## 发布验证

[`reports/`](../reports/) 目录包含 release-safe 的兼容性执行、模板覆盖、公共数据库检查、结构和单细胞验证、确定性证据、插件安装和公共数据案例摘要。这些报告保留具体验证结果，但不暴露私有路径、凭据或开发过程账本。

详细版本基线表由模块注册表和兼容性报告生成，而不是在本指南中重复维护。这样用户文档保持可读，同时机器可验证证据仍位于源头。

## 凭据与外部服务

公共客户端使用有边界的 schema、host allow-list、响应限制、identifier 保留，以及显式截断或冲突状态。可选 API key 通过用户环境或认可的 secret surface 提供，不能硬编码。凭据不会进入执行 artifact、报告、示例或 commit。
