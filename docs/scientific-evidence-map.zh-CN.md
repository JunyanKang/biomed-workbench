# 科学证据地图、版本管理与双语报告

Biomed Workbench 把项目保存为持续演进的科学论证，而不是只保留成功输出的文件夹。地图分为两层：

1. **项目主线图**：只显示图组或关键数据之间支持、削弱、冲突和依赖关系，让读者先看懂完整研究故事；
2. **单项证据展开图**：对每份数据或每个图组依次追踪前置结论、登记数据、作图数据、分析程序、排图程序、最终数据与图文件、图注、叙述来源和原始研究 DOI。

每个文件绑定工作区内可跳转路径、媒体类型、大小和文件校验指纹。报告生成前重新检查路径与指纹；文件缺失或改变会阻止生成。供系统核对的关系记录与阅读版地图来自同一组关系，二者的校验值共同进入双语报告。

## 分析前准入

每个分析节点执行前必须登记：

- 中英文科学依据和可证伪假设；
- 方法、官方说明与主要方法来源；
- 备选方案和选择理由；
- 假设条件与逐参数依据；
- 预期产物；
- 接受、证伪和阻断标准。

信息不足的节点可以保留为计划，但不能被当成已授权分析或有效证据。

证据地图明确区分三种用途。`project-snapshot` 用于如实展示已通过资格审查的输入、待执行分支、失败、冲突与排除项；它不满足论文或其他正式交付的放行条件。`delivery-authorization` 在一个发表交付节点执行前建立：只覆盖该节点的全部上游节点和明确绑定的输入产物，要求上游均已完成，输入均已评审并保留，且执行、重读、评审、决策和计划绑定共同形成不可漂移的上游证据切片；它只授权登记的那个交付节点，不要求尚未执行的交付节点先完成。交付产物重新读取、评审并保留后，`validated-delivery` 才作为全计划终态归档，要求当前活动计划的每个节点均已完成、每个末端交付产物的明确身份均已保留。两个节点即使输出同类数据，也不能用其中一个已完成结果掩盖另一个待执行、待评审、失败或跳过的分支。

## 逐项科学评审与决策

外部交接产生的产物在评审前，必须先为每个待处理模块门禁建立独立科学审议，精确绑定实际执行回执、输出端口、结构化门禁结果校验值和证据文件校验值。产物评审必须登记完整审议集合。被拒绝或未解决的门禁仍可进入严重或致命等级评审，以支持排除、重跑、更换方法、补充数据、修订计划或停止分支，但绝不能被保留为当前有效证据。当前不可评定的门禁只有在明确记录带限制接受，并作出带限制保留决策时，才能进入有效证据集。

所有数据、表格、模型、图和中间产物均分别接受技术、统计、生物学和稳健性评审。图形需要按图中分区逐项解释，不能用一段总述代替。

评审后可以保留、带限制保留、排除、重跑、换方法、补数据、调整假设或停止分支。只有前两种进入当前有效证据集。保留会完成当前节点并释放证据；排除和停止会终止当前分支但保留完整历史。评审选择重跑或换方法时，系统先通过实时方法注册表创建不可变的子计划，再登记科学决策。节点级修订契约同时固定来源节点与目标节点、动作、两个方法清单、登记的替代关系、输入输出契约、原执行与新执行的请求身份、完整目标参数、科学等价类别、结论范围变化和科学理由；同一次来源执行产生的全部输出必须共用同一契约、动作、目标和请求身份，不能拆成相互矛盾的去向。替代节点保持分支、假设、依赖、输入和输出身份一致，尚未执行的下游节点会改接到新产物身份；原方法原参数重跑保持实际请求身份不变，调整参数重跑登记不同请求身份，换方法使用原模块清单声明的端口兼容替代方法。真正等价的方法必须使用相同质量门禁；承担相同决策角色但证据类型不同的方法会清除来源方法的门禁结论，并重新执行目标方法的门禁、评审与准入；范围降级则明确收窄可主张的结论。替代节点执行前还需单独通过分析准入。补数据会把分支置于等待新输入状态；调整假设或项目范围会请求新的不可变研究计划版本。失败、冲突和负结果始终保留在证据地图中。

## 版本与报告

证据地图采用不可覆盖的版本目录，每个版本记录父版本、变更原因、登记内容和校验信息。地图文件、版本索引、当前版本指针和项目状态登记通过带恢复记录的发布事务提交；准备阶段会另存按内容寻址的待登记项目状态。若过程被中断，恢复检查会明确标出暂存、未入索引或未登记到项目状态三类状态，并列出当前唯一安全的操作。只有当前状态仍等于事务前状态、待登记状态及其校验值正确、不可变版本索引和当前指针均匹配时，显式完成恢复才会写入项目状态。若中断发生在 `prepared` 阶段，只有确认项目状态未变、待登记状态与发布身份正确，并且不存在暂存目录、未入索引目录、索引记录、当前指针或不可变版本时，才允许显式放弃并重试；出现任何已发布文件歧义都必须人工审查。

已经绑定旧证据地图的第一版项目状态通过独立、非覆盖式迁移恢复。迁移会先验证旧状态摘要和事件链，再依据版本索引、登记文件校验值、地图内容和发布身份重新读取每个旧地图。由迁移契约 1.1.0 生成的第二版状态也必须非覆盖式升级：旧状态摘要、迁移与恢复记录摘要、事件链、不可变地图、计划节点合同和地图覆盖关系全部通过后，才写出独立的 1.2.0 后继状态；后继状态同时记录旧状态与旧迁移摘要及升级原因。未指定具体交付节点时，交付条件明确写为尚未评估，不能以空列表推断为失败。新状态把旧发布记录为已验证的不可变历史，但不把它们冒充为新版状态下仍然有效的当前地图；在新地图明确以上一个旧地图为父版本、并重新绑定迁移后状态之前，正式交付持续阻断。旧状态文件和旧地图内容始终保留原样。

中英文报告只能从同一张通过验证的地图生成，并覆盖每项产物的科学依据、方法、结果、结论、限制、决策和对下一步的影响。报告生成器不得自行重新拼接来源。
