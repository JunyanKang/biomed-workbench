# 项目锁定、分析选择与结果状态

## 工作模式与既有项目

`EXPLORE` 用于快速查看候选结果和尝试临时图件；其结果可以保留为候选、敏感性分析或废弃结果，但不能直接进入正式证据。`FORMALIZE` 用于固定实验单位、分析方法、参数、作图数据、权威脚本和科学解释。`SUBMISSION` 用于最终可复现交付，要求正式结果、图件约定、科学证据地图、成图视觉复核、隐私检查和独立复现彼此一致。

对于已经积累了大量文件的项目，`project import-existing` 只读扫描指定目录，不改动原文件。它会盘点可能的图件、作图数据、分析脚本、排图程序、图注和已有 panel 登记表，并说明每条候选关系来自文件名对应还是脚本中的明确引用。`project confirm-import` 要求研究者逐条确认或拒绝；只有经过确认且不存在版本冲突的关系才能用于建立项目锁定，文件名相似本身不构成数据来源证明。

项目还可以提供带版本的生物学背景配置。它把原始论文支持的领域知识与本项目观察严格分开，为已有认识登记 DOI，明确物种、组织、发育阶段或疾病背景和细胞区室，并记录不能跨越的推断、其他可能解释以及能够区分这些解释的观察。这份配置用于辅助科学复核，不会自动证明某个结论，也不能替代领域专家判断。

普通结果页只呈现生物学问题、主要观察、解释边界、当前进度和下一步决定。运行环境、文件校验和与完整项目记录保留在可复现性和详细记录视图中，按需查看。

语言：[中文](project-governance.zh-CN.md) · [English](project-governance.md)

Biomed Workbench 以科学问题和研究决策为中心组织长期项目。它不会因为某个方法可用，就把所有候选分析都加入流程；也不会因为程序运行成功，就把结果直接放入正式论文图。

## 先理解问题，再选择方法

系统先分别识别实验类型、测量靶标、对照、归一化方式和需要判断的生物学关系，并保留否定条件和术语歧义。例如，“继发转录效应”属于下游表达变化，不会被解释为 RNA 二级结构；S9.6 实验中的 spike-in 用于归一化，不能替代 RNase H 特异性证据。

复杂课题会拆分为若干可以独立评审的科学分支，最后设置一个综合判断节点。每个科学问题默认只选择：

- 一个直接回答问题的主分析；
- 一个使用不同假设、数据层或误差结构的正交验证。

第三种方法只有在明确替代现有分析，或能提供现有两种方法没有提供的决策信息时，才进入执行。这样可以减少方法之间反复切换，也避免同一结论被多个高度相关的方法重复包装。

## 项目锁定配置

正式分析开始前，项目会锁定样本表、基因组与注释版本、细胞注释、条件比较的生物学重复单位、分析环境身份、阈值、颜色含义、正式结果目录和论文图登记表。每个文件都记录版本和内容指纹。实际执行后，环境身份随执行回执保存；再次分析前先核对并优先复用已有兼容环境，避免重复安装和不易察觉的依赖变化。

这些内容发生变化时，需要建立新的项目锁定版本，并保留上一版本的关联。旧结果不会通过修改图注、移动目录或更换文件名自动适配新配置；受影响的分析和图件需要重新评审。

## 四种结果状态

| 状态 | 含义 | 可以进入正式论文图吗 |
| --- | --- | --- |
| `CANDIDATE` | 已获得结果，但仍在等待充分评审或比较 | 否 |
| `SENSITIVITY` | 用于检验参数、假设或方法依赖性的结果 | 否，除非之后完成正式晋级 |
| `FORMAL` | 已完成真实运行、结果重读、科学评审、保留决策和项目锁定核对 | 是 |
| `DEPRECATED` | 已被替代、排除或不再用于当前结论 | 否 |

从候选或敏感性结果晋级为正式结果，不是修改一个标签。系统会核对实际运行与结果重读记录、模块的方法验证范围、双语科学评审、保留决定、实验单位、项目锁定配置，以及论文图规格。正式结果仍只能支持其研究设计和数据实际允许的结论。

## 能力成熟度

面向用户的项目页面只使用四级：`CONTRACT_ONLY`、`EXECUTED_FIXTURE`、`PUBLIC_CASE_VALIDATED` 和 `CURRENT_PROJECT_VALIDATED`。一个能力包含多种方法时，会单独列出已经通过公共案例的方法，不会因为其中一种方法通过就把整个能力写成公共案例已验证。各级含义和当前分母见[能力成熟度](maturity.zh-CN.md)。

## 结果优先的项目视图

日常交互默认显示科学结论、关键结果、证据边界、当前状态和下一项决策。版本、文件指纹、执行记录、评审链和完整历史仍被保存，但不占据主要结果页面；需要追溯、复现或处理阻断问题时再展开。

论文图、图注、结果文字和双语报告仍从同一版本的[科学证据地图](scientific-evidence-map.zh-CN.md)读取。每个版本的 HTML 报告和证据地图都带有目录及文件、图件和文献入口，便于从结论直接返回数据与来源，避免项目状态、图件编号和叙述来源彼此漂移。

## 从结果形成研究故事

正式图件不按“有哪些分析”来堆叠，而按科学论证需要组织。每个图面先确定它承担发现、时空或细胞来源、机制一致性、正交验证、边界与阴性结果或跨数据整合中的哪一项任务。相邻图面需要形成递进关系；只重复同一贡献、没有改变判断的信息不会因为显著或美观就自动进入主图。

工作台还会把项目的生物学背景带入解释复核：物种、组织、发育时期、疾病状态和细胞区室需要与观察相符；文献知识、当前项目结果和待检验假说分别陈述。发现解释过强时，处理方式是修正文稿、缩小结论、补充能够区分解释的分析或实验，或排除结果，而不是增加一页问题清单。完整方法见[科学解释、研究叙事与结果决策](capabilities/scientific-interpretation-and-storytelling.zh-CN.md)。
