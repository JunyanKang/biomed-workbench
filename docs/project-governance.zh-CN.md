# 项目锁定、分析选择与结果状态

语言：[中文](project-governance.zh-CN.md) · [English](project-governance.md)

Biomed Workbench 以科学问题和研究决策为中心组织长期项目。它不会因为某个方法可用，就把所有候选分析都加入流程；也不会因为程序运行成功，就把结果直接放入正式论文图。

## 先理解问题，再选择方法

系统先分别识别实验类型、测量靶标、对照、归一化方式和需要判断的生物学关系，并保留否定条件和术语歧义。例如，“继发转录效应”属于下游表达变化，不会被解释为 RNA 二级结构；S9.6 实验中的 spike-in 用于归一化，不能替代 RNase H 特异性证据。

复杂课题会拆分为若干可以独立评审的科学分支，最后设置一个综合判断节点。每个科学问题默认只选择：

- 一个直接回答问题的主分析；
- 一个使用不同假设、数据层或误差结构的正交验证。

第三种方法只有在明确替代现有分析，或能提供现有两种方法没有提供的决策信息时，才进入执行。这样可以减少方法之间反复切换，也避免同一结论被多个高度相关的方法重复包装。

## 项目锁定配置

正式分析开始前，项目会锁定样本表、基因组与注释版本、细胞注释、条件比较的生物学重复单位、分析环境身份、阈值、颜色含义、正式结果目录和论文图登记表。每个文件都记录版本和内容指纹。实际执行后，环境身份随执行回执保存；再次分析前先核对并优先复用已有兼容环境，避免重复安装和不易察觉的依赖变化。

这些内容发生变化时，需要建立新的项目锁定版本，并保留上一版本的关联。旧结果不会通过修改图注、移动目录或更换文件名自动适配新配置；受影响的分析和图件需要重新评审。

## 四种结果状态

| 状态 | 含义 | 可以进入正式论文图吗 |
| --- | --- | --- |
| `CANDIDATE` | 已获得结果，但仍在等待充分评审或比较 | 否 |
| `SENSITIVITY` | 用于检验参数、假设或方法依赖性的结果 | 否，除非之后完成正式晋级 |
| `FORMAL` | 已完成真实运行、结果重读、科学评审、保留决策和项目锁定核对 | 是 |
| `DEPRECATED` | 已被替代、排除或不再用于当前结论 | 否 |

从候选或敏感性结果晋级为正式结果，不是修改一个标签。系统会核对实际运行与结果重读记录、模块的方法验证范围、双语科学评审、保留决定、实验单位、项目锁定配置，以及论文图规格。正式结果仍只能支持其研究设计和数据实际允许的结论。

## 三个不同的验证问题

| 标记 | 回答的问题 |
| --- | --- |
| `engineering_validated` | 登记的实现是否真实执行过受控案例，并重新读取了规定输出？ |
| `method_validated` | 对应方法是否还有当前有效的代表性或公共数据案例？ |
| `project_promoted` | 当前项目中的这个具体结果是否已经通过正式晋级？ |

三者不能互相替代。工程测试通过不代表方法适用于任意实验；公共案例通过不代表当前项目完成；模块登记中的历史 `validated` 标签只描述注册合同类别，不作为科学完成结论。

## 结果优先的项目视图

日常交互默认显示科学结论、关键结果、证据边界、当前状态和下一项决策。版本、文件指纹、执行记录、评审链和完整历史仍被保存，但不占据主要结果页面；需要追溯、复现或处理阻断问题时再展开。

论文图、图注、结果文字和双语报告仍从同一版本的[科学证据地图](scientific-evidence-map.zh-CN.md)读取。每个版本的 HTML 报告和证据地图都带有目录及文件、图件和文献入口，便于从结论直接返回数据与来源，避免项目状态、图件编号和叙述来源彼此漂移。
