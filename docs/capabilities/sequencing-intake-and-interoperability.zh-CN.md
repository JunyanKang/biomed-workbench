# 测序输入、运行准备与外部流程衔接

[中文](sequencing-intake-and-interoperability.zh-CN.md) · [English](sequencing-intake-and-interoperability.md) · [返回能力地图](README.zh-CN.md)

这组能力负责把 FASTQ、BAM/CRAM、VCF、单细胞矩阵、样本表和参考资源可靠地送入后续分析，并把已经完成的外部测序流程结果重新接回项目。它解决的是“输入是什么、现在能不能运行、运行结果能不能被可信地读取”三个不同问题。

## 输入检查

`sequencing-input-intake` 会读取文件身份和少量结构信息，识别 FASTQ、BAM/CRAM、变异文件、单细胞矩阵、表格及常见参考文件；同时检查重复路径、缺失文件、双端读段是否成对，以及样本表中的样本标识是否完整且唯一。它根据已声明的实验类型给出下一步分析方向，但不会仅凭文件名推断文库化学、链特异性、实验分组或生物学质量。

## 运行前准备

`sequencing-execution-readiness` 分开核对两类条件：

- 分析软件是否已经存在；
- 参考基因组、注释、索引、blacklist、known-sites、分类数据库或 barcode whitelist 等资源是否存在且非空。

通过这一步只表示启动条件齐备。实际版本兼容性、流程是否成功和结果是否可解释，仍由所选分析模块及其运行结果决定。工作台不会在这个阶段自动安装软件或重复建立已有环境。

## 接收外部流程结果

`sequencing-run-package-ingest` 读取外部流程的 `manifest.json` 与 `artifact_index.json`。只有状态明确为完成、产物真实存在、路径未越出运行目录、文件校验值一致，并记录了分析环境身份的运行包才会进入后续质量与科学复核。仅生成计划、处于准备或阻断状态、运行失败或没有有效产物的目录不会被当作分析完成。

这一接口可以接收由其他专业测序流程生成的标准运行包，同时保持 Biomed Workbench 自己的输入、环境、结果和科学结论边界。原始读段质控、比对、定量、变异检测、peak calling、微生物组或单细胞 count generation 仍需由对应的正式执行流程完成；接收运行包不是这些计算的替代品。

## 典型用法

> 检查这些 FASTQ、样本表和参考基因组是否足以开始 bulk RNA-seq；先告诉我缺什么，再复用已有环境运行合适的流程。

> 读取这个外部测序流程的运行目录，确认它是否真的完成、产物是否完整以及使用了哪个分析环境；通过后再做结果质控和生物学解释。
