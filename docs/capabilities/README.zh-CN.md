# 专业能力概览

语言：[中文](README.zh-CN.md) · [English](README.md) · 项目首页：[中文](../../README.md) · [English](../../README.en.md)

Biomed Workbench 按研究问题组织能力。用户提供科学目标和数据后，工作台会组合需要的方法，从证据检索和研究设计推进到数据分析、结果复核、假设调整和科研交付。

## 写作能力如何衔接研究

工作台不会把写作简化为末端润色。文献身份、全文位置、项目事实、分析结果、图表和引用先形成可以复核的写作依据；证据再按科学问题、前后依赖和在论证中的作用重排，而不是沿用上传顺序或逐方法罗列。论文结构、段落和项目申请论证在这个基础上建立。修订阶段分别检查生命科学或医学表达、内容保持、统计报告、数据可用性和目标期刊要求；最终写作生成可跳转到项目证据与文献的 HTML 阅读页，并在交付前重新打开。同行评议阶段再连接审稿意见、逐条回复、真实修改和稿件位置。图件、演示和专利材料复用已经评审的项目证据，但分别遵循自己的交付要求。

用户可以只请求其中一步，也可以要求从文献和项目数据推进到完整稿件。具体任务、输入和交付物见[科研写作、发表与转化交付](publication-and-translation.zh-CN.md)，自然语言示例见[使用指南](../using-biomed-workbench.zh-CN.md)。

## 工作台怎样组合这些能力

简单问题可能只需要一个数据库或一种分析。复杂项目可以把多个方向连接起来，例如先检查研究设计和数据质量，再完成差异分析、通路与网络解释、结构证据补充、论文图和稿件撰写。

相互独立的工作可以并行推进；依赖上游结果的分析会按顺序执行。每一步都会记录使用的数据、方法、质量检查和对下一步的影响，避免在项目变长后丢失科学逻辑。

复杂问题不会只按相似词选择工具。工作台先分开理解实验方法、测量靶标、对照、归一化和待判断的生物学关系，再建立独立分析分支和最终综合判断。例如，“继发转录效应”不会被误识别为 RNA 二级结构；多组学、R-loop、蛋白互作和 RNA 加工可以进入各自分支，最后共同回答直接作用与下游效应的关系。

既有项目可以先只读盘点图件、作图数据、分析脚本、排图程序和图注，待研究者逐条确认后再建立正式关系。日常页面只显示科学问题、主要观察、解释边界、当前进度和下一步决定；完整环境、参数和文件来源按需展开。

## 当前覆盖范围

当前注册表包含 **222 个可独立识别的模块**。每个模块都对应带版本的科学执行约定；对外成熟度另行区分只有执行约定、已运行受控测试、具体方法已通过公共案例，以及当前项目结果已正式纳入。具体状态和代表性案例见[能力成熟度](../maturity.zh-CN.md)和[公共数据案例](../cases/README.zh-CN.md)。

Bulk 层覆盖 RNA-seq 与 RNA 加工/可变剪接；ChIP-seq、CUT&RUN 与 CUT&Tag；多种 R-loop 测量；RIP-seq、CLIP 系列与 LACE-seq；Ribo-seq；GRO-seq、PRO-seq、TT-seq 与 NET-seq；ATAC-seq 与 DNase-seq；WGBS、RRBS 与 EM-seq；多种三维基因组方法；以及 MeRIP-seq/m6A-seq。

实验方法、检测靶标、抗体、对照、特异性处理和归一化策略会分别记录。例如 CUT&Tag 是实验方法，S9.6 是靶标或抗体信息，外源内参是归一化选择，RNase H 处理提供特异性证据；它们不会被误列为彼此并列的实验类型。

测序输入会先经历文件、样本配对、软件和参考资源检查；外部流程返回后，只有状态完整、产物可重新读取、文件身份一致且分析环境明确的运行包才能进入结果复核。单细胞和空间能力保留平台及方法的专属要求；通用方法负责跨数据尺度复用的设计、统计、富集、网络和结果评审。结果复核优先呈现观察值、效应大小、不确定性和实验单位，并检查结论是否超出研究设计、是否遗漏阴性结果，以及下一步能否区分竞争性解释。科学作图作为全项目支撑规范，约束各方向的字体、线条、颜色、图例、标注、版面、源数据和导出检查，但不取代方法专属诊断图或定量图像分析。论文与转化能力连接经过评审的研究证据、图表、引用和文字交付，并保留稿件修订与审稿回复的对应关系。期刊适配指引会注明所依据规范的版本和复核日期，并以期刊与出版机构官网为研究范围、文章类型和投稿要求的权威来源。

## 如何理解结果边界

工作台会明确区分数据是否存在与是否足够、技术重复与独立生物学样本、相关性与因果证据、数据库记录与生物学解释、预测置信度与实验验证，以及计算结束与科学结论成立。

缺少必要输入、兼容软件或质量证据时，相应结论会保持未解决。对方法开发和新增模块感兴趣的读者可查看[架构与扩展](../architecture.zh-CN.md)。
